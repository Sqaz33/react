# Инструкции для занятий в репозитории D:\react

Этот репозиторий используется для подготовки пользователя к позиции
«Стажёр Frontend React разработчик, AoS B2B, МТС Веб Сервисы».

## Перед началом каждого занятия

Обязательно прочитать полностью:

1. `LEARNING_PLAN.md` — цель, программа и критерии готовности.
2. `PROGRESS.md` — текущее место в программе и следующий шаг.
3. `STUDENT_CONTEXT.md` — уже знакомые технологии и формат обучения.
4. `REACT_THEORY.md` — краткий конспект уже разобранной и текущей теории.

После чтения продолжать с поля «Следующее действие» в `PROGRESS.md`, если
пользователь не попросил изменить направление.

## Формат обучения

- Общаться на русском языке.
- Объяснять новую концепцию до того, как она потребуется в задании.
- Давать содержательные задания в основном проекте, обычно по одному связному
  результату; не заменять практику серией микрошагов или упражнениями в Console.
- Основную учебную реализацию пишет пользователь. Не выдавать целиком готовое
  решение и не присылать исправленный фрагмент текущего задания, если пользователь
  явно об этом не попросил: назвать проблему, причину и требуемое изменение.
- До задания дать достаточную теорию и полный минимальный синтаксис нового API:
  аргументы, результат и типичные ошибки. Если неизвестна отдельная конструкция,
  показать нейтральный пример, не собирающий готовое решение текущего задания.
- После присланного решения сначала проверить его и объяснить причины ошибок,
  затем давать следующий шаг.
- При каждой проверке интерфейса отдельно оценивать HTML и CSS: семантику,
  доступность, подходящие элементы и атрибуты, структуру классов, раскладку и
  адаптивность. Давать практические советы по улучшению, даже если текущий урок
  посвящён React или JavaScript. Не превращать проверку в замечания о пробелах.
- Связывать React с уже знакомым пользователю Vue 3, но отдельно отмечать места,
  где аналогия неточная (`watch` и `useEffect`, `computed` и `useMemo` и т. п.).
- Сначала использовать React с JavaScript. TypeScript вводится после уверенного
  владения базовым React.
- Не считать тему освоенной только потому, что она была объяснена. Для отметки
  «освоено» нужно выполненное пользователем задание, корректный ответ или иное
  проверяемое подтверждение.
- Сохранять пользовательский код и не переписывать его без необходимости.

## После каждого значимого шага

Обновить `PROGRESS.md`:

- дату последнего занятия;
- текущий модуль и урок;
- что пользователь сделал самостоятельно;
- что проверено и освоено;
- ошибки или темы для повторения;
- одно конкретное следующее действие;
- короткую запись в журнале занятий.

Делать это автоматически, когда обновление уместно; не ждать отдельного
напоминания пользователя о ведении учебных документов.

Если программа изменилась по договорённости с пользователем, обновить также
`LEARNING_PLAN.md`. Не удалять историю завершённых этапов.

После начала или завершения теоретической темы обновлять также
`REACT_THEORY.md`: сохранять краткое объяснение, ключевой синтаксис и типичные
ошибки. Не отмечать тему пройденной раньше, чем это подтверждено практикой или
проверяемым ответом пользователя.

## Учебный проект

Основной проект — Todo/Task Board, постепенно приближаемый к небольшому B2B
приложению. Он должен использоваться для React, JavaScript, HTML/CSS, SCSS,
Styled Components, Git, API, тестов, code review и браузерных инструментов.
