- `App` передаёт массив задач в `TodoList`, а список создаётся через `map`.

## Журнал занятий

### 2026-09-21 — начаты правила хуков

- Разбирается связь состояния React с неизменным порядком вызовов hooks между
  рендерами и два основных правила: только верхний уровень и только React-функции.
- Практика: вынести знакомые `useState`/`useEffect` debounce в собственный
  `useDebouncedValue`, не меняя интерфейс и поведение Todo.

### 2026-09-22 — первая проверка `useDebouncedValue`

- Debounce успешно вынесен в собственный hook; state, effect, таймер, cleanup и
  возвращаемое значение расположены в нём, а `App` вызывает hook на верхнем уровне.
- API hook пока содержит лишний `startValue`: по контракту достаточно
  `(value, delay)`, а начальный state должен создаваться из `value`.
- В dependency array отсутствует `delay`; линтер сообщает предупреждение
  `exhaustive-deps`. В `App` также остались неиспользуемые imports `useEffect` и
  `useDebugValue`, а остальные hooks не перенесены в единый блок в начале компонента.
- HTML улучшен: статистика переведена со случайных `span` на семантический `dl`,
  а `label` поиска корректно связан с input. Checkbox задачи всё ещё не имеет
  доступного имени, а сообщение сохранения стоит сделать live-region.
- CSS действия задачи устроен разумно через flex, однако фиксированная высота
  кнопки приоритета может обрезать текст, а горизонтальный header без wrapping
  плохо переносит узкую ширину.
- Production-сборка проходит; линтер выдаёт три содержательных предупреждения.

### 2026-09-22 — правила hooks приняты

- Создан рабочий `useDebouncedValue(value, delay)`: начальный state берётся из
  `value`, effect зависит от `value` и `delay`, cleanup отменяет старый таймер.
- Все hooks в `App` собраны в начале компонента и вызываются безусловно;
  неиспользуемые imports удалены, результат назван `debouncedSearchText`.
- Пользователь закрепил, что custom hook — обычная JavaScript-функция,
  переиспользующая hooks, а не отдельный компонент или отдельное состояние.
- `npm run lint` и `npm run build` проходят без предупреждений и ошибок.
- По HTML/CSS улучшены семантика статистики и размеры action-кнопок. В очереди
  улучшений остаются label checkbox, live-region для `saveMessage`, wrapping
  header и удаление повторного правила `.todo-actions`; они не блокируют урок.

### 2026-09-22 — повторная проверка `useDebouncedValue`

- Сигнатура hook исправлена на `(value, delay)`, `delay` добавлен в зависимости,
  неиспользуемые imports удалены, а все hooks перенесены в начало `App`.
- Вызов в `App` по ошибке остался трёхместным: `useDebouncedValue("",
  searchText, 400)`. В JavaScript лишний аргумент игнорируется, поэтому hook
  получает `value === ""` и `delay === searchText`; поиск фактически перестаёт
  фильтровать, хотя линтер и сборка проходят.
- Фиксированная высота кнопки удалена, общий padding действий задан осознанно.
  Однако live-region добавлен к сообщению «Все задачи завершены», а не к
  `saveMessage`; checkbox остаётся без доступного имени, `.todo-actions`
  определён в CSS дважды, а header всё ещё не переносит элементы.
- Дополнительно разобрана граница ререндера: локальный state запускает повторное
  вычисление компонента-владельца и его поддерева, а собственный hook не является
  отдельным узлом — его state принадлежит вызывающему компоненту.

### 2026-09-21 — начат event loop

- Разбираются call stack, браузерные Web APIs, очереди tasks и microtasks.
- Практика связана с текущим fake-save: нужно отметить ключевые точки выполнения
  и объяснить порядок сообщений для успешного и ошибочного результата.
- Пользователь решил не расставлять временные логи. Верно объяснено, что executor
  `new Promise` выполняется синхронно, а callback `setTimeout` запускается позже
  как task; урок продолжается короткой проверкой порядка без изменения проекта.

### 2026-09-21 — event loop принят

- Пользователь правильно определил порядок `1 → 4 → 3 → 2`: сначала
  синхронный код, затем microtask Promise и после неё task таймера.
- Закреплена цепочка текущего fake-save: callback таймера вызывает
  `resolve`/`reject`, после чего продолжение `async`-функции после `await`
  выполняется как microtask.
- Тема отмечена в плане пройденной; следующий урок — debounce на поиске.

### 2026-09-21 — начат debounce на поиске

- Сначала строится обычный поиск как исходная версия: controlled input хранится
  в `App`, а видимый список вычисляется без отдельного state.
- После проверки обычного поиска будет добавлено второе, отложенное поисковое
  значение и отмена предыдущего таймера — непосредственно механизм debounce.

### 2026-09-21 — debounce на поиске принят

- `searchText` немедленно управляет полем, а отдельное отложенное значение
  обновляется через 400 мс и используется для вычисления `visibleTodos`.
- Effect создаёт таймер при изменении строки, а cleanup отменяет предыдущий;
  серия быстрых вводов приводит к одному итоговому обновлению после паузы.
- Поиск вынесен в `TodoSearch`, к нему добавлена небольшая flex-раскладка.
- Название `debounceSearchText` рабочее, но более точная форма для результата —
  `debouncedSearchText`; рекомендация не блокирует принятие урока.
- `npm run lint` и `npm run build` проходят; пробелы не рассматриваются как
  блокирующие замечания по просьбе пользователя.
- Тема отмечена пройденной; следующий урок — правила хуков.
