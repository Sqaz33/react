## Проверено и освоено в этом репозитории

- Самостоятельно создан Vite-проект React с JavaScript.
- Самостоятельно объявлены и подключены `TodoHeader`, `TodoForm`, `TodoList` и
  `TodoItem`.
- `App` передаёт массив задач в `TodoList`, а список создаётся через `map`.
- Исправлено понимание специального атрибута `key`: он остаётся на `TodoItem` в
  родительском списке и не извлекается из props внутри `TodoItem`.
- Выполненные задачи отображаются через условный `className` и CSS-класс.
- Статический `TodoForm` содержит форму, поле и кнопку.
- Линтер и production-сборка проходят успешно.
- `TodoForm` самостоятельно переведён на локальный state через `useState`.
- Поле связано со state через `value` и `onChange`; счётчик символов подтверждает
  ререндер после `setTitle`.
- На практике использован JSX-фрагмент без лишнего DOM-контейнера.
- Массив `todos` переведён в state общего родителя `App`.
- `TodoForm` сообщает о добавлении через callback-prop `onAddTodo`.
- Новая задача добавляется функциональным setter без мутации старого массива.
- Отправка формы работает через `onSubmit`, `preventDefault`, валидацию и очистку
  controlled input.
- `App` иммутабельно переключает `completed` нужной задачи через функциональный
  setter, `map` и object spread.
- Callback `onToggleTodo` передаётся через `TodoList` в `TodoItem`.
- Checkbox является controlled input: `checked` получает значение из
  `item.completed`, а `onChange` сообщает родителю `item.id`.
- На практике закреплён один источник истины: состояние задачи хранится только
  в `App`, а `TodoItem` не дублирует его локально.
- Удаление задачи реализовано без мутации через функциональный setter и
  `filter`; callback `onDeleteTodo` проходит от `App` до `TodoItem`.
- Кнопка удаления имеет явный `type="button"` и понятное текстовое название.
- `total` и `remaining` вычисляются при рендере из `todos` без дублирующего
  state и передаются props в `TodoHeader`.
- Закреплена связь JSX-классов и CSS-селекторов, включая несколько классов на
  элементе, flex-раскладку и сброс стандартных отступов списка.
- `TodoList` использует ранний возврат для пустого массива и показывает понятное
  сообщение вместо пустого списка без отдельного state.
- `TodoLayout` принимает вложенный JSX через `children`, возвращает общую
  оболочку `<main>` и используется в `App` для композиции интерфейса.
- Пользователь различает чистые вычисления во время рендера, отложенные
  обработчики событий, мутацию state и внешние побочные эффекты.
- Пользователь понимает цепочку `index.html → main.jsx → App`, роли основных
  файлов Vite-проекта и преобразование JSX в JavaScript сборщиком.
- Пользователь ранее владел базовым циклом Git и отдельно освоил просмотр
  staged diff и diff конкретного файла.
- На практике реализованы локальный JSON Server, HTTP GET/POST/PATCH/DELETE,
  проверка `response.ok`, сериализация JSON и пессимистичное обновление Todo.
- Состояния API `idle/loading/success/error` моделируются reducer; error/status и
  empty-state доходят до интерфейса.
- Query первоначальной загрузки и server mutations имеют независимые состояния.
- `App` отвечает за представление, `useTodos` — за server state и операции над
  задачами, `todoApi` — только за HTTP transport.
- Первоначальный список начинается с `[]`; loading, error и успешный empty-state
  различаются, а изменяющие элементы блокируются во время server mutation.
- `AbortController` отменяет первоначальный GET при cleanup, request id
  отбрасывает устаревший результат, а конфликтующие mutations пока запрещаются
  общей блокировкой.
- Составные операции дублирования и удаления выполненных задач перенесены из
  `App` в `useTodos`; ручная fake-кнопка сохранения удалена из рабочего UI.
- `toggleTodo` переведён на optimistic update: checkbox меняется до ответа,
  success подтверждается объектом server-response, ошибка откатывает только
  прежнее значение `completed`.
- Закреплён CORS: origin определяется протоколом, host и port; разрешение
  сообщает server через response headers, а JSON-запрос может вызвать preflight
  `OPTIONS`. `mode: "no-cors"` не является исправлением.
- Установлен актуальный React Router в Declarative Mode; `BrowserRouter`
  находится над `App`, а `Routes`/`Route` сопоставляют URL и page-компоненты.
- Созданы `/todos`, `/settings` и wildcard 404; `/` канонически перенаправляется
  через `Navigate replace`, внутренние переходы выполняются через `Link`.
- Прямой GET `/settings` на Vite development server возвращает `index.html` с
  кодом 200, поэтому refresh вложенного SPA-route работает локально.
- Pathless `AppLayout` остаётся смонтированным между child routes, владеет
  `useTodos`, темой, общей навигацией и единственным `<main>`.
- `Outlet context` передаёт Todo server state и actions в `TodoPage`; переходы
  на настройки и обратно больше не пересоздают `useTodos` и не запускают новый
  GET из-за смены child route.
- Пользователь различает чистую client SPA, MPA, CSR, SSR, SSG и гибрид: для
  интерактивного B2B-кабинета SPA уместна, публичные content routes чаще выгодно
  предварительно рендерить на server или build-time.
- Реализован динамический route `/todos/:todoId`; `useParams` вызывается на
  верхнем уровне page-компонента, а задача находится по значению параметра URL.
- Ссылка на заголовке задачи использует относительный `to={item.id}` и ведёт от
  `/todos` к `/todos/:todoId` без полной перезагрузки документа.
- Страница задачи различает loading, network error, resource not found и
  success; успешные данные размечены через `article`, `h1` и description list.
- Поиск списка использует URL-параметр `q` как единственный источник истины:
  controlled input восстанавливается после refresh, а debounce применяется к
  уже прочитанному из URL значению.
- Обновление query string копирует текущий `URLSearchParams`, поэтому не удаляет
  независимые параметры; пустое значение удаляет `q`, а `replace` не засоряет
  browser history промежуточными буквами.
- Общая навигация использует `NavLink`: callback формирует базовый и активный
  классы, а раздел задач остаётся активным на `/todos/:todoId`.
- Route 404 содержит понятный заголовок и объяснение; кнопка вызывает
  `useNavigate(-1)` и возвращает по browser history.

## Требует внимания

- Помнить: команды npm выполняются в каталоге `D:\react\react`, где находится
  `package.json`.
- React изучается с начального уровня: сначала теория и разбор кода, затем
  маленькая практика. Не предполагать знание React по прошлым кратким беседам.
- При разъяснении одного неизвестного API не собирать полный код задания:
  объяснить минимальный синтаксис и оставить интеграцию пользователю.
- Перевести знакомую Vue-модель на React, не механически копируя аналоги.
- Укреплять HTML/CSS параллельно с React.
- При каждом review отдельно проверять HTML/CSS и предлагать конкретные
  улучшения семантики, доступности и раскладки; не зацикливаться на пробелах.
- Перед заданиями по HTML/CSS разбирать новые термины и синтаксис селекторов,
  свойств и значений; не ограничиваться готовой строкой CSS без объяснения.
- При первом использовании аббревиатуры давать её полную расшифровку, перевод
  или буквальный смысл и только затем пользоваться сокращением.
- Позже отдельно отработать Git, тесты, code review и современные браузеры —
  это требования целевой вакансии.
- Текущая блокировка допускает только одну mutation за раз. Позже отдельно
  изучить независимые pending-состояния по `id` и параллельные операции.
- `useApi.js` содержит старый учебный `useLocalStorage`; файл оставлен как
  материал для просмотра и не участвует в рабочем приложении.
- Пессимистичная модель пока очищает поле добавления независимо от результата:
  если понадобится сохранять ввод при ошибке, контракт action должен сообщать
  форме об успехе или неудаче.

### 2026-09-21 — начаты Promise и async/await

- Разбираются состояния `pending`, `fulfilled`, `rejected`, обработчики

- Для практики выбран пользовательский async-обработчик сохранения с видимыми
  loading/success/error состояниями; HTTP и `useEffect` пока не вводятся.
