# Краткий конспект React

Последнее обновление: **2026-09-21**

Этот файл повторяет теорию в порядке наших уроков. Отметка «пройдено» означает,
что тема была не только объяснена, но и проверена на практике. Подробный маршрут

## 0. Проект и запуск — пройдено

- React-приложение находится в `D:\react\react`.
- Команды npm выполняются там, где лежит `package.json`.
- `npm run dev` запускает сервер разработки.
- `npm run lint` проверяет код, `npm run build` собирает production-версию.
- `main.jsx` создаёт корень React и подключает глобальный `index.css`.
- `App.jsx` — корневой компонент текущего интерфейса.

## 1. React, React DOM и рендер — пройдено

- `react` даёт компоненты, JSX-модель, state и хуки.
- `react-dom` связывает React с браузерным DOM.
- `createRoot(...).render(<App />)` запускает первоначальный рендер.
- Рендер — вычисление того, как должен выглядеть интерфейс сейчас.
- Commit — применение необходимых изменений к настоящему DOM.
- После изменения state React может заново вызвать компоненты, но React DOM
  изменяет только отличающиеся части страницы, а не пересоздаёт весь документ.

## 2. Функциональные компоненты — пройдено

Компонент — функция с именем с заглавной буквы, возвращающая JSX:

```jsx
function TodoHeader() {
  return <h1>Todo</h1>
}
```

- Пользовательский компонент используется как `<TodoHeader />`.
- `export default` экспортирует компонент, `import` подключает его в другом
  модуле.
- Компонент должен возвращать один корневой JSX-элемент или фрагмент.

## 3. JSX — пройдено

- JSX похож на HTML, но является синтаксисом JavaScript.
- JavaScript-выражение вставляется через `{...}`.
- Атрибут класса называется `className`, обработчики — `onClick`, `onChange`.
- Имена многих DOM-свойств записываются в camelCase.
- Все теги закрываются, включая `<input />`.
- Несколько соседних элементов можно обернуть во фрагмент `<>...</>`.
- `true`, `false`, `null` и `undefined` сами по себе ничего не рисуют.
- В обработчик передают функцию, а не результат её немедленного вызова.

## 4. Props — пройдено

Props — входные данные компонента от родителя:

```jsx
function TodoHeader({total}) {
  return <span>Всего: {total}</span>
}
```

- Props доступны только для чтения: ребёнок не должен их изменять.
- Деструктуризация `{total}` достаёт свойство из объекта props.
- Изменение props родителем приводит к новому рендеру ребёнка.

## 5. Списки, `map` и `key` — пройдено

- `map` вызывает callback для каждого элемента и создаёт новый массив той же
  длины.
- В React `map` часто превращает массив данных в массив JSX-элементов.
- У элементов списка нужен стабильный `key`, обычно идентификатор записи.
- `key` помогает React сопоставлять старые и новые элементы списка.
- `key` — специальный атрибут React: он не попадает в props компонента.

## 6. State и `useState` — пройдено

```js
const [title, setTitle] = useState('')
```

- `title` — снимок состояния для текущего рендера.
- `setTitle` просит React сохранить новое значение и запланировать рендер.
- Изменять state напрямую нельзя: React узнаёт об обновлении через setter.
- Если новое значение зависит от предыдущего, используется функциональная
  форма: `setValue(current => nextValue)`.

## 7. События, формы и controlled input — пройдено

- Обработчик получает объект события: `onChange={event => ...}`.
- `event.preventDefault()` отменяет стандартную отправку формы.
- `type="submit"` отправляет форму, `type="button"` выполняет обычное действие.
- Controlled input получает `value` из state и обновляет его в `onChange`.
- Checkbox управляется свойством `checked`, а не `value`.

Поток controlled input:

```text
ввод → onChange → setter → рендер → новое value/checked
```

## 8. Подъём состояния и callback-props — пройдено

- Общее состояние хранится у ближайшего общего родителя.
- Родитель передаёт данные вниз через props.
- Ребёнок сообщает о событии вверх через переданную функцию-callback.

Поток Todo:

```text
TodoItem → callback → App → setTodos → рендер → новые props
```

Промежуточный `TodoList` может только передавать callback дальше. Такая цепочка
называется prop drilling; для небольшого дерева она нормальна.

## 9. Иммутабельные обновления — пройдено

State нельзя менять методами `push`, `splice` или мутирующим `sort`.

- Добавление: создать новый массив через spread.
- Переключение: `map` возвращает новый массив, а изменяемая задача копируется
  через object spread.
- Удаление: `filter` возвращает массив без задачи с выбранным `id`.

Функциональный setter даёт актуальное предыдущее состояние, но не разрешает его
мутировать. Нужно вернуть новое значение с новой ссылкой.

## 10. Один источник истины — пройдено

- `completed` хранится только в массиве `todos` внутри `App`.
- `TodoItem` не создаёт вторую копию `completed` в локальном state.
- Checkbox читает `item.completed` и сообщает родителю только `item.id`.
- Дублирование одного значения в нескольких state приводит к рассинхронизации.

## 11. Минимальное состояние и вычисляемые значения — пройдено

- В state хранится только то, что нельзя полностью вычислить из других state
  или props.
- `total = todos.length` и количество невыполненных вычисляются при рендере.
- Для простых вычислений не нужны отдельные state, Effect или `useMemo`.
- После изменения `todos` компонент вызывается снова, поэтому производные
  значения автоматически пересчитываются.
- Во Vue ближайшая аналогия — `computed`, но в React часто достаточно обычной
  переменной в теле компонента.

## 12. Условный рендеринг — пройдено

- Ранний `return` удобен, когда компонент должен вернуть полностью другой JSX.
- Тернарный оператор выбирает один из двух вариантов:
  `condition ? trueJSX : falseJSX`.
- `condition && jsx` показывает элемент только при истинном условии.
- С числом нужно писать `items.length > 0 && ...`, иначе React может вывести
  `0`.
- Пустота списка вычисляется через `todos.length`, отдельный `isEmpty` state не
  нужен.

## 13. Композиция и `children` — пройдено

- JSX между открывающим и закрывающим тегами компонента попадает в специальный
  prop `children`.
- Компонент-оболочка определяет структуру, а родитель определяет содержимое.
- `children` подходит для layout, panel, card и modal.
- Данные с конкретным смыслом (`total`, `todos`) остаются обычными props.
- Во Vue ближайшая аналогия — default slot.

## 14. Чистота рендера — пройдено

Компонент во время рендера должен вести себя как чистая функция от props, state
и context:

- одинаковые входы должны давать одинаковый JSX;
- нельзя мутировать props, state и существующие внешние объекты;
- нельзя вызывать setters прямо во время рендера;
- нельзя во время рендера выполнять `fetch`, менять DOM, запускать таймеры или
  записывать в `localStorage`;
- разрешено читать данные, создавать новые локальные значения, использовать
  чистые `map`/`filter` и объявлять обработчики событий.

`onClick={() => setValue(...)}` только создаёт обработчик; setter выполнится
после клика. `onClick={setValue(...)}` вызывает setter немедленно при рендере и
может создать бесконечный цикл.

React может повторять или отменять render phase, а `StrictMode` в разработке
помогает замечать нечистую логику. Побочные эффекты выполняются в обработчиках
событий или, когда нужна синхронизация с внешней системой, в `useEffect`, который
будет изучен позже.

Проверка пройдена: чистыми распознаны вычисление производного значения через
`filter` и создание функции-обработчика. Мутация state через `push`, немедленный
вызов setter в JSX и запись в `localStorage` правильно распознаны как
недопустимые во время рендера.

## 15. CSS, встреченный в проекте

- Глобальный CSS подключён в `main.jsx` через `import './index.css'`.
- В JSX пишется `className="todo-item"`, в CSS — `.todo-item`.
- Несколько классов в JSX разделяются пробелом:
  `className="todo-item completed"`.
- `.todo-item.completed` означает один элемент с двумя классами.
- `.todo-item .todo-title` означает потомка внутри `.todo-item`.
- `display: flex` располагает дочерние элементы по основной оси; `gap` задаёт
  промежутки, `align-items` выравнивает по поперечной оси.
- `margin-left: auto` забирает свободное место перед flex-элементом и прижимает
  его вправо; порядок DOM при этом не меняется.
- `max-width` ограничивает ширину, а `margin: ... auto` центрирует блок.
- У `<ul>` есть браузерные `margin`, `padding` и маркеры; их можно сбросить.
- CSS не может выбрать отдельный текстовый узел, поэтому название задачи
  обёрнуто в `.todo-title` для отдельного зачёркивания.

## 17. Устройство Vite-проекта — пройдено

Цепочка запуска:

```text
npm → package.json scripts → Vite → index.html → main.jsx → App → компоненты
```

- `package.json` описывает проект, npm-скрипты и зависимости.
- `package-lock.json` фиксирует точные версии всего дерева npm-зависимостей;
  обычно он обновляется npm и коммитится вместе с `package.json`.
- `node_modules` содержит установленные пакеты, генерируется через npm и не
  коммитится.
- `index.html` — HTML-оболочка с `<div id="root">` и подключением `main.jsx`.
- `src/main.jsx` — точка входа JavaScript: подключает CSS и `App`, создаёт React-
  корень и запускает первоначальный рендер.
- `src/App.jsx` — обычный, а не магический компонент; корневым он становится,
  потому что `main.jsx` передаёт `<App />` в `render`.
- `src` содержит исходный код и импортируемые ресурсы, которые обрабатывает
  Vite.
- `public` содержит статические файлы, доступные от корня сайта без импорта и
  без преобразования сборщиком, например `/favicon.svg`.
- `vite.config.js` настраивает Vite; React-плагин обрабатывает React/JSX.
- `dist` — сгенерированный результат `npm run build`; его не редактируют вручную
  и в этом проекте не коммитят.
- `.gitignore` перечисляет генерируемые и локальные файлы, которые Git должен
  игнорировать, включая `node_modules` и `dist`.

Браузер не выполняет JSX напрямую. В режиме разработки Vite принимает запрос к
`/src/main.jsx`, преобразует JSX через React-плагин и отдаёт браузеру обычный
JavaScript-модуль. При `npm run build` Vite заранее преобразует и собирает код в
файлы внутри `dist`; браузер в production также получает JavaScript, а не JSX.

Обычная клиентская сборка Vite создаёт статические файлы `index.html`, CSS и
JavaScript. Код используемых `react` и `react-dom` включается в JavaScript-бандл
(возможны несколько файлов при разделении кода), минифицируется и загружается
браузером. Это не означает, что весь интерфейс заранее превращён в HTML:
`index.html` по-прежнему содержит корневой контейнер, а React DOM после загрузки
JavaScript создаёт и обновляет DOM на клиенте. Предварительный HTML требует
отдельного SSR или static generation, которых в текущем проекте нет.

## 18. Базовый цикл Git — пройдено

Git хранит три основных состояния:

```text
рабочая папка → staging area (index) → история коммитов
              git add              git commit
```

- Рабочая папка содержит текущие файлы и незакоммиченные изменения.
- Staging area содержит выбранную версию файлов для следующего коммита.
- Коммит — сохранённый снимок только staged-изменений с сообщением и автором.
- `git status` показывает изменённые, staged и untracked-файлы.
- `git diff` показывает unstaged-изменения относительно staging area.
- `git add <path>` помещает текущую версию выбранного файла в staging area; он
  не создаёт коммит и не отправляет код в интернет.
- `git diff --staged` показывает, что именно войдёт в следующий коммит.
- `git commit -m "сообщение"` создаёт локальный коммит из staged-изменений.
- `git log --oneline` показывает краткую историю коммитов.
- Коммит остаётся локальным; отправка в удалённый репозиторий выполняется
  отдельной командой `git push`, которая в этот урок не входит.

В diff строки с `-` удалены, строки с `+` добавлены, а строки без такого
префикса показаны для контекста. Лучше добавлять конкретные файлы, а не слепо
использовать `git add .`, если в рабочей папке есть несвязанные изменения.

Пользователь уже владел базовыми командами. Новыми вариантами стали
`git diff --staged` для просмотра будущего коммита и
`git diff -- path/to/file` для просмотра выбранного файла.

## 19. `find`, `some`, `every` — пройдено

Все три метода принимают callback с условием и не изменяют исходный массив:

- `find` возвращает первый подходящий элемент или `undefined`;
- `some` возвращает `true`, если подходит хотя бы один элемент;
- `every` возвращает `true`, если подходят все элементы.

Методы прекращают перебор, когда результат уже известен. Для пустого массива
`some` возвращает `false`, а `every` — `true`: нет ни одного элемента,
нарушающего условие. Перед использованием результата `find` нужно учитывать
возможный `undefined`.

Практика в Todo: `find` определяет следующую невыполненную задачу, `some`
показывает наличие хотя бы одной выполненной, а `every` — состояние «выполнены
все». Все три значения вычисляются из `todos` во время рендера без нового state.

Для пользовательского состояния «все задачи выполнены» перед `every` нужна
проверка `todos.length > 0`, иначе пустой массив даст `true`. Boolean-значения
получили говорящие имена `hasCompletedTodos` и `areAllTodosCompleted`, а результат
`find` проверяется перед чтением данных найденной задачи.

## 20. `reduce` — пройдено

`reduce` последовательно сворачивает массив в одно итоговое значение. Итогом
может быть число, строка, объект или массив.

```js
const result = items.reduce((accumulator, currentItem) => {
  return nextAccumulator
}, initialValue)
```

- `accumulator` хранит результат предыдущего шага;
- `currentItem` — текущий элемент массива;
- `initialValue` становится аккумулятором перед первым элементом;
- значение, возвращённое callback, становится аккумулятором следующего шага;
- после последнего элемента `reduce` возвращает финальный аккумулятор.

Начальное значение лучше передавать явно: с ним понятен тип аккумулятора, а
пустой массив возвращает это значение. Без начального значения пустой массив
вызывает ошибку. Частая ошибка — забыть `return`, после чего на следующем шаге
аккумулятор станет `undefined`.

`reduce` не заменяет остальные методы: для преобразования обычно яснее `map`,
для отбора — `filter`, для поиска — `find`, для boolean-проверок — `some` или
`every`. Он нужен, когда из набора элементов собирается одно итоговое значение.

Практика в Todo: `completedCount` вычисляется с аккумулятором-числом и начальным
значением `0`. Явное условие возвращает `sum + 1` для выполненной задачи и
неизменённый `sum` для невыполненной. Сложение числа с boolean технически
работает через преобразование `true`/`false` в `1`/`0`, но явное условие понятнее.

## 21. `sort` — пройдено

`.sort(compareFunction)` упорядочивает элементы и возвращает ссылку на тот же
массив. Без функции сравнения значения приводятся к строкам и сравниваются как
текст, поэтому числовой порядок может оказаться неожиданным.

Функция сравнения получает два элемента `a` и `b`:

- отрицательное число — `a` должно стоять раньше `b`;
- положительное число — `b` должно стоять раньше `a`;
- `0` — их относительный порядок менять не нужно.

Для чисел по возрастанию используется `a - b`, по убыванию — `b - a`. Для строк
подходит `a.localeCompare(b)`.

Обычный `.sort()` мутирует массив. Поэтому нельзя вызывать `todos.sort(...)` на
массиве из React-state. Сначала создаётся новый массив через `[...todos]`, и уже
его можно сортировать. Сортировка для отображения является вычисляемым значением:
ей не нужны отдельный state, setter или Effect. Современный `toSorted()` сразу
возвращает копию, но в первой практике используется копирование плюс `.sort()`,
чтобы явно закрепить мутацию этого метода.

Хорошая функция сравнения чистая и предсказуемая: не меняет элементы, не вызывает
setter и для одной пары всегда возвращает одинаковый результат. Для равных по
критерию элементов нужно возвращать `0`; современная стабильная сортировка тогда
сохраняет их исходный относительный порядок. Возвращать именно `-1` и `1` не
обязательно — важен знак числа. Поля с известным типом сравниваются строго через
`===`.

Практика в Todo: `[...todos]` создаёт копию state, а comparator
`Number(a.completed) - Number(b.completed)` помещает `false` (`0`) раньше
`true` (`1`). При одинаковых значениях разность равна нулю, поэтому относительный
порядок задач одной группы сохраняется. В `TodoList` передаётся `sortedTodos`, а
исходный `todos` остаётся источником данных для остальных вычислений.

## 22. Объекты, spread/rest и деструктуризация — пройдено

Объект хранит связанные именованные свойства. Запись `const copy = original`
копирует только ссылку: обе переменные указывают на один объект. Object spread
в выражении объекта создаёт новый внешний объект:

```js
const updated = { ...todo, completed: true }
```

Свойства применяются слева направо, поэтому более позднее `completed` заменяет
скопированное. Обратный порядок `{ completed: true, ...todo }` восстановил бы
старое значение из `todo`.

Деструктуризация извлекает свойства в переменные:

```js
const { title, completed } = todo
```

Object rest находится слева при разборе объекта и собирает оставшиеся свойства:

```js
const { title, ...todoData } = todo
```

В `{ ...todoData, title }` тот же синтаксис уже является spread: он раскрывает
свойства в новый объект. Короткая запись `title` равна `title: title`.

Spread выполняет поверхностное копирование. Внешний объект становится новым, но
вложенный объект сохраняет старую ссылку. Для изменения вложенного уровня нужно
копировать каждый изменяемый уровень отдельно. В React это важно для
иммутабельного обновления state; props также нельзя изменять.

Практика в Todo: копия задачи создаётся через spread исходного объекта, после
чего более поздние `id`, `title` и `completed` заменяют старые значения. В
`TodoList` деструктуризация `{ todos, ...itemProps }` отделяет список, а rest
собирает остальные callback-props; JSX spread передаёт их в каждый `TodoItem`.
Rest не является обязательным при простой перезаписи свойств — в таком случае
прямой `{ ...original, changed: value }` часто понятнее.

## 23. Ссылочное равенство и мутация — пройдено

Примитивы сравниваются по значению, а объекты и массивы — по ссылке. Два отдельно
созданных одинаковых объекта не равны через `===`; две переменные равны, если
указывают на один объект. `const` запрещает переназначить переменную, но не
запрещает менять свойства объекта или элементы массива.

Мутация изменяет существующий объект. Для React-state это нарушает модель
снимков: старые рендеры и другие ссылки начинают видеть изменённые данные, а
передача setter той же ссылки может не запланировать ожидаемое обновление.

Spread копирует только один уровень:

```js
const nextTodos = [...todos]
```

Массив новый, но `nextTodos[0] === todos[0]`. Аналогично `{ ...todo }` создаёт
новую задачу, но вложенное `details` остаётся той же ссылкой. При изменении
`details.priority` иммутабельное обновление должно создать новые ссылки на массив,
изменяемую задачу и `details`; неизменённые задачи полезно вернуть как есть.

React сравнивает старое и новое значение state через семантику `Object.is`.
Новая ссылка сообщает, что контейнер изменился, но сама по себе не делает
вложенные данные независимыми. Копировать нужно каждый изменяемый уровень, а не
всё дерево без разбора.

Практика в Todo: при переключении `details.priority` через `map` создаются новый
массив, новая выбранная задача и новый `details`; другие задачи возвращаются как
есть. Неизменённые вложенные объекты также могут сохранять старые ссылки — это
структурное разделение, а не ошибка. Новая задача сразу получает полную ожидаемую
форму с `details`, иначе JavaScript-сборка не заметила бы отсутствующее поле, а
ошибка проявилась бы только при чтении в браузере.

Полное копирование и обновление существующего state имеют разные цели. При
обновлении копируется путь к изменяемому значению. При создании отдельного
дубликата сущности допустим `structuredClone`, если требуется независимость всех
поддерживаемых вложенных данных; это осознанное решение, а не обязательный шаблон
для каждого обновления.

## 24. Scope, closures и callbacks — пройдено

Scope определяет, где доступно имя. `let` и `const` имеют блочную область
видимости, параметры и локальные переменные функции доступны только внутри неё,
а вложенная функция может читать имена из внешней лексической области.

Callback — функция, переданная другому коду для последующего вызова. В Todo
callback вызывают методы массивов, React setter и система событий. Передача
`onClick={handler}` передаёт функцию, а `onClick={handler()}` вызывает её во время
рендера и передаёт результат.

Closure (замыкание) возникает, когда функция сохраняет доступ к лексическому
окружению места создания. В обычном JavaScript замыкаются привязки переменных. В
React каждый рендер создаёт новый набор локальных значений и обработчиков, поэтому
обработчик конкретного рендера видит props/state этого рендера — его снимок.

В `onClick={() => onToggleTodo(item.id)}` стрелочная функция замыкает `item.id` и
`onToggleTodo`. В `currentTodos => ...` React сам передаёт актуальный предыдущий
state аргументом. Если новое состояние зависит от текущего, setter-callback
предпочтительнее чтения `todos` из замыкания.

Updater-функция должна быть чистой: React в Strict Mode может вызвать её повторно
для проверки. Поэтому получение времени, случайного значения и другие нечистые
действия выполняются в обработчике события до setter, а готовое значение можно
замкнуть и использовать внутри updater.

Практика в Todo: `duplicateTodo(id)` создаёт `newId` в обработчике, затем передаёт
React чистый updater. React вызывает его с актуальным `curTodos`; updater замыкает
`id` и `newId`. Вложенный callback `find` отдельно получает текущий `todo` от
самого метода массива. Если задача не найдена, возвращается прежний массив; если
найдена — новый массив с дубликатом.

## 25. ES-модули — пройдено

Каждый файл с `import`/`export` является модулем и имеет собственную область
видимости: его локальные имена не становятся глобальными. Экспорт делает выбранное
значение доступным другим модулям, а импорт создаёт доступ к экспортированной
привязке.

Named exports позволяют экспортировать несколько значений и импортируются в
фигурных скобках под точными именами. Их можно переименовать через `as`. Default
export в модуле может быть только один и импортируется без фигурных скобок; имя
при импорте выбирает получатель. Текущие React-компоненты используют default
export, но компоненты не требуют его — это обычное соглашение проекта.

Статические `import` располагаются на верхнем уровне. Vite строит по ним граф
зависимостей, преобразует JSX и собирает production-файлы. Код верхнего уровня
модуля выполняется один раз при загрузке модуля, после чего его exports
переиспользуются. Импортированные привязки нельзя переназначать.

Циклических зависимостей (`a` импортирует `b`, а `b` импортирует `a`) лучше
избегать. Чистые константы и функции предметной логики удобно хранить в обычном
`.js`-модуле, который ничего не знает о React-компонентах.

Практика в Todo: модуль `priority.js` предоставляет named exports
`PRIORITY_LABELS` и `getNextPriority`. `TodoItem` импортирует данные для
отображения, а `App` — чистую функцию предметной логики. Компоненты не импортируются
обратно в utility-модуль, поэтому граф зависимостей направлен в одну сторону и не
содержит цикла.

## 26. Promise, async/await и try/catch/finally — пройдено

Promise представляет будущий результат асинхронной операции. Он создаётся в
состоянии `pending`, затем один раз переходит в `fulfilled` со значением или в
`rejected` с причиной ошибки. После этого Promise считается settled и повторно
изменить его результат нельзя.

`.then` обрабатывает успешное значение, `.catch` — отклонение, `.finally`
выполняется после любого исхода и не получает результат операции. Каждый вызов
возвращает новый Promise, поэтому обработчики образуют цепочку; возвращённое
значение становится результатом следующего шага, а `throw` переводит цепочку в
rejected.

Функция с `async` всегда возвращает Promise. `await` можно использовать внутри
`async`: он ждёт settlement, возвращает fulfilled-значение или выбрасывает
rejection как исключение. `await` приостанавливает только текущую async-функцию,
а не блокирует браузер.

`try` содержит ожидаемую операцию и success-логику, `catch` получает ошибку, а
`finally` подходит для обязательной очистки — например, снятия `isSaving` при
успехе и ошибке. Async-действие, вызванное кликом, остаётся в обработчике события;
для него не требуется `useEffect`.

Практика в Todo: `saveTodos` создаёт Promise и вызывает `resolve`/`reject` внутри
callback `setTimeout`, поэтому задержка действительно определяет settlement.
Пустая функция таймера сама по себе не является ожиданием: `setTimeout` лишь
регистрирует callback и немедленно возвращает идентификатор.

`handleSaveTodos` включает loading, очищает старое сообщение и ожидает сервис.
Успешное значение обрабатывается в `try`, `Error` — в `catch`, а `finally`
снимает loading при любом исходе. Во время pending кнопка disabled и показывает
`Сохранение...`; HTTP и Effect для действия по клику не нужны.

## 27. Event loop — пройдено

Синхронный JavaScript выполняется в call stack до его освобождения. Таймеры и
события обслуживает окружение браузера; готовые callback-функции попадают в
очередь tasks. Продолжение после `await` и обработчики Promise попадают в очередь
microtasks.

После завершения текущей task движок выполняет все накопившиеся microtasks, затем
браузер получает возможность отрисовать изменения и берётся следующая task.
`setTimeout(callback, 0)` означает «не раньше указанной задержки», а не
«выполнить немедленно». `await` приостанавливает только текущую async-функцию и
не блокирует интерфейс.

Проверочный порядок для синхронных `console.log`, `Promise.resolve().then(...)`
и `setTimeout(..., 0)` определён верно: сначала выполняется весь синхронный код,
потом microtask Promise и только затем task таймера. В текущем fake-save callback
таймера вызывает `resolve` или `reject`, что ставит продолжение после `await` в
очередь microtasks.

## 28. Debounce на поиске — пройдено

Debounce откладывает вызов функции до тех пор, пока события не прекратятся на
заданное время. Каждый новый вызов отменяет предыдущий таймер и создаёт новый.
Поэтому серия быстрых вводов приводит к одному итоговому запуску после паузы.

Простой `setTimeout` на каждое событие не является debounce: без
`clearTimeout` выполнятся все созданные callbacks. Debounce использует замыкание,
чтобы помнить идентификатор предыдущего таймера между вызовами. В поиске обычно
разделяются немедленное значение поля и отложенное значение, по которому
запускается дорогая фильтрация или сетевой запрос.

В React поле должно оставаться отзывчивым: `searchText` обновляется при каждом
вводе, а отдельное отложенное значение меняется только после паузы. Effect при
изменении `searchText` создаёт новый таймер; его cleanup вызывает `clearTimeout`
перед следующим effect и тем самым отменяет устаревшее обновление.

Практика в Todo: controlled-компонент `TodoSearch` передаёт мгновенную строку в
`App`, а `visibleTodos` фильтруется по значению, обновляемому через 400 мс после
последнего ввода. Сортировка сохраняется, статистика продолжает вычисляться по
полному массиву задач.

## 29. Правила хуков — пройдено

React связывает внутренние ячейки состояния с порядком вызовов hooks во время
рендера. Поэтому hooks вызываются только на верхнем уровне компонента или
собственного hook: не внутри условий, циклов, вложенных функций и не после
условного раннего возврата.

Hooks вызываются только из React-компонентов и собственных hooks. Обычная
JavaScript-функция не должна вызывать `useState` или `useEffect`. Имя собственного
hook начинается с `use`, а имя компонента — с заглавной буквы. Вызов setter в
обработчике разрешён: setter не является hook, hook был вызван при рендере.

Custom hook — обычная JavaScript-функция с именем, начинающимся на `use`. Она
выполняется во время рендера вызывающего компонента, может принимать аргументы и
возвращать значения. Особого синтаксиса нет; специальны правила вызова и
возможность использовать внутри другие hooks. Каждый вызов получает независимое
состояние React и переиспользует логику, а не один общий state.

Практика в Todo: `useDebouncedValue(value, delay)` содержит `useState` и
`useEffect`, возвращает отложенное значение и вызывается безусловно в начале
`App`. После его появления debounce-логика исчезла из компонента, а поведение
поиска осталось прежним.

## 30. `useEffect` и внешняя синхронизация — пройдено

Рендер должен оставаться чистым: по props и state он вычисляет JSX и не изменяет
внешний мир. `useEffect` нужен, когда после commit требуется синхронизировать
компонент с системой вне React: браузерным API, таймером, подпиской, соединением
или сторонним виджетом.

Effect состоит из setup и необязательного cleanup. При изменении зависимости
React сначала выполняет cleanup предыдущего effect со значениями предыдущего
рендера, затем запускает новый setup. При удалении компонента выполняется
последний cleanup. В режиме разработки Strict Mode React дополнительно проверяет
симметрию последовательностью setup → cleanup → setup.

Все реактивные значения, прочитанные setup или cleanup, должны находиться в
dependency array. React сравнивает каждую зависимость с прошлой через
`Object.is`. Без массива effect запускается после каждого commit, с `[]` — после
первого commit, а с `[a, b]` — также после изменения `a` или `b`.

`navigator.onLine` является обычным снимком браузерного состояния и сам не
запускает React-рендер. State служит реактивным мостом: браузерное событие
вызывает setter, React рендерит компонент и custom hook возвращает новое значение.
Возврат из setup — инструкция cleanup для React, а возврат из custom hook — его
обычный результат для вызывающего компонента.

Практика в Todo: `useOnlineStatus` постоянно слушает оба события `online` и
`offline`, меняет state соответствующими обработчиками и удаляет обе подписки в
cleanup. Подписка существует всё время жизни компонента, поэтому effect имеет
пустой dependency array. Статус передаётся в `TodoHeader` и выводится через
`dd` с `role="status"`.

## 31. События и Effects — пройдено

Обработчик события запускается потому, что произошло конкретное взаимодействие:
клик, submit или изменение поля. Effect запускается потому, что компонент
отображается и должен оставаться синхронизированным с внешней системой при
изменении зависимостей. Асинхронность сама по себе не определяет выбор.

Действие пользователя не следует превращать в state-флаг, за которым наблюдает
Effect: обработчик уже знает точную причину и должен выполнить действие напрямую.
Effect, наоборот, не вызывается вручную — React управляет его setup и cleanup в
соответствии с жизнью компонента и dependency array.

Асинхронность не определяет выбор: запрос сохранения по кнопке относится к
обработчику, а подписка на внешний источник во время присутствия компонента — к
Effect. Корректные зависимости и cleanup предотвращают накопление таймеров и
подписок, но не являются причиной переносить пользовательское действие в Effect.

Практика в Todo: кнопка «Удалить выполненные» напрямую вызывает переданный из
`App` обработчик. Он через функциональный setter и `filter` оставляет только
незавершённые задачи; отдельные state-флаг и Effect не создаются.

## 32. `localStorage` без лишних Effects — пройдено

`localStorage` — синхронное браузерное хранилище строк, привязанное к origin.
`getItem(key)` возвращает строку или `null`, а `setItem(key, value)` сохраняет
строку. Объекты и массивы требуют явных `JSON.stringify` и `JSON.parse`.

Начальное чтение state не следует выполнять Effect после первого рендера: это
сначала покажет fallback, затем вызовет второй рендер. Lazy initializer
`useState` читает сохранённое значение только при создании состояния. Запись при
изменении `todos` является настоящей синхронизацией React-state с внешней
системой и может выполняться одним Effect.

Lazy initializer передаётся как функция без вызова: `useState(load)`. В отличие
от него Effect с `[]` выполняется лишь после первого commit, поэтому загрузка
через setter дала бы сначала пустой интерфейс и второй рендер. Effect без массива
выполнялся бы после каждого commit и мог создать цикл обновлений.

Практика в Todo: `storage.js` содержит fallback, чтение, проверку массива и
запись JSON. `App` получает начальный `todos` через lazy initializer, а Effect с
зависимостью `[todos]` сохраняет любые последующие изменения. При отсутствии
ключа loader возвращает начальные задачи, которые Effect затем записывает в
хранилище; имена ключей регистрозависимы.

## 33. `useRef` и DOM — пройдено

`useRef(initialValue)` возвращает один стабильный объект `{ current }`, который
сохраняется между рендерами. В отличие от state, изменение `.current` не просит
React выполнить новый рендер. Поэтому ref подходит для данных, которые нужно
помнить, но которые сами по себе не отображаются в JSX.

При передаче ref DOM-элементу через атрибут `ref` React после commit записывает в
`.current` реальный узел браузера, а при удалении узла устанавливает `null`.
DOM-ref используют из обработчика или Effect, а не читают как источник данных
для JSX во время рендера.

Ref не заменяет controlled state: state хранит отображаемое значение и вызывает
рендер, а ref предоставляет императивный доступ к DOM без рендера. Ref следует
размещать у ближайшего компонента, которому действительно нужен узел; поднимать
его в родителя без внешнего управления не требуется.

Практика в Todo: `TodoForm` хранит `title` в state и локальный `inputRef` отдельно.
После успешного submit задача добавляется, state очищается, а вызов
`inputRef.current?.focus()` возвращает курсор в существующий input без Effect.

Рендер компонента планируется при обновлении его state, при рендере родителя с
его дочерним элементом или при изменении читаемого context/внешнего store. При
локальном state React отмечает соответствующий Fiber и путь до корня; в
прикладной модели повторно вычисляются компонент-владелец state и его потомки,
а несвязанные предки и соседние ветки не вызываются заново. React может
пропустить потомка через bailout, например при `memo` и неизменных props.

Собственный hook не создаёт узел дерева: его state принадлежит компоненту,
который вызвал hook. Поэтому setter внутри `useDebouncedValue`, вызванного из
`App`, планирует рендер `App`. Render повторно вызывает функции компонентов и
строит новое описание UI; commit применяет только реальные различия к DOM.

## Частые ошибки, которые уже встречались

- Запуск npm не в каталоге с `package.json`.
- Попытка прочитать специальный `key` внутри props.
- Передача результата вызова вместо функции в обработчик.
- Использование `value` вместо `checked` у checkbox.
- Дублирование `completed` в локальном state.
- Мутация текущего массива и возврат той же ссылки из setter.
- CSS-класс написан в JSX через точку вместо пробела.
- Путаница между `.a.b` (один элемент с двумя классами) и `.a .b` (потомок).
- Неявный `type="submit"` у кнопки.
- Вывод чисел без понятных текстовых подписей.
