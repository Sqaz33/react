# Контекст ученика

## Цель

Подготовиться к позиции «Стажёр Frontend React разработчик, AoS B2B, МТС Веб
Сервисы»: пройти от переноса имеющейся Vue-базы на React до самостоятельной
разработки, тестирования, работы с Git и разбора кода на уровне стажёра.

## Исходная база

Пользователь изучал:

- Vue 3;
- JavaScript;
- базовые HTML и CSS;
- компонентный подход, props и события;
- формы и списки;
- фильтрацию, поиск и сортировку;
- `localStorage`;
- основы `Promise` и `async/await`.

В Vue был учебный Todo-проект. Знакомство с темой не означает автоматически
полное владение: знания проверяются заново на React-практике.

React изучается с начального уровня. Предыдущие краткие объяснения React не
считаются достаточной теоретической базой. Нельзя давать задание на новую тему,
пока не разобраны её смысл, синтаксис, выполнение кода и отличие от Vue.

## Предпочтительный формат

- обучение на реальном развивающемся проекте;
- содержательные задания в основном проекте `D:\react\react`, без лишнего
  дробления на микрошаги и без Console-практики вместо проекта;
- сначала объяснение новой конструкции, потом применение;
- теория должна быть достаточной, чтобы выполнить задание осознанно, а не по
  догадке или копированию образца; для нового API нужны форма аргументов,
  возвращаемое значение и типичные ошибки;
- пользователь пишет основную часть кода самостоятельно; при review ассистент
  не присылает готовое исправление без отдельной явной просьбы;
- при вопросе о незнакомом синтаксисе нужен минимальный пример только этой
  конструкции, без готового решения всего текущего задания;
- проверка кода после каждого шага;
- при проверке проекта нужны отдельные замечания и советы по HTML/CSS, а не
  только по React/JavaScript; форматирование пробелов само по себе не является
  приоритетом;
- сравнение с Vue там, где оно помогает пониманию;
- русский язык объяснений.
- учебные документы и журнал прогресса обновляются автоматически после
  значимых шагов, без отдельного напоминания пользователя.

## Технологический порядок

1. React + JavaScript + Vite.
2. HTML/CSS и SCSS внутри проекта.
3. Styled Components как второй способ стилизации.
4. REST API и асинхронная работа.
5. Тестирование.
6. TypeScript после устойчивой базы React, если останется время до отбора.

## Текущая контрольная точка

- Модули 0–6 пройдены; модуль 7 о SPA и маршрутизации начат.
- Рабочая архитектура: `App` отображает UI, `useTodos` управляет server state,
  `todoApi` выполняет React-независимые HTTP-запросы.
- Пользователь различает query (`GET`) и mutation (`POST/PATCH/PUT/DELETE`), а
  также server mutation и прямую мутацию JavaScript-объекта.
- Query загрузки и mutations имеют отдельные reducer-state; на текущем этапе
  разрешена только одна mutation за раз, controls блокируются.
- На `toggleTodo` реализованы optimistic update и точечный rollback; пользователь
  проверил success и отключённый server, различает optimistic и pessimistic flow.
- CORS изучен на уровне frontend-диагностики: origin, server headers, preflight
  `OPTIONS` и бесполезность `mode: "no-cors"` как обхода.
- Подключён React Router 7 Declarative Mode: пользователь понимает отношение
  `BrowserRouter → App → Routes → Route`, использует `Link`, wildcard 404 и
  канонический redirect через `Navigate replace`.
- Todo state пока находится внутри `TodoPage` и теряется при переходе на другую
  страницу; следующий архитектурный шаг — общий layout route с `Outlet`.
- Старые учебные `fakeTodoService`, `saveReducer` и ошибочно названный
  `useApi.js` пользователь намеренно оставляет для последующего просмотра; не
  удалять их автоматически и не подключать к рабочему приложению.
