# Контекст ученика

## Цель

Подготовиться к позиции «Стажёр Frontend React разработчик, AoS B2B, МТС Веб
Сервисы»: пройти от переноса имеющейся Vue-базы на React до самостоятельной
разработки, тестирования, работы с Git и разбора кода на уровне стажёра.

## Исходная база

Пользователь изучал:

- Vue 3;
- JavaScript;
- базовые HTML и CSS;
- компонентный подход, props и события;
- формы и списки;
- фильтрацию, поиск и сортировку;
- `localStorage`;
- основы `Promise` и `async/await`.

В Vue был учебный Todo-проект. Знакомство с темой не означает автоматически
полное владение: знания проверяются заново на React-практике.

React изучается с начального уровня. Предыдущие краткие объяснения React не
считаются достаточной теоретической базой. Нельзя давать задание на новую тему,
пока не разобраны её смысл, синтаксис, выполнение кода и отличие от Vue.

## Предпочтительный формат

- обучение на реальном развивающемся проекте;
- полная теория по новой теме на взрослом техническом уровне; не сокращать
  содержание темы, но не разбирать очевидные части команд как отдельные уроки;
- новая теория сразу закрепляется изменением основного проекта в
  `C:\react\react`; изолированные упражнения в Console используются только для
  диагностики, если без них нельзя локализовать проблему;
- один пункт `LEARNING_PLAN.md` проходится за 1–2, максимум 3 содержательных
  задания и обращения к пользователю, без чрезмерного дробления на микрошаги;
- сначала объяснение новой конструкции, потом применение;
- теория должна быть достаточной, чтобы выполнить задание осознанно, а не по
  догадке или копированию образца;
- для нового API обязательно нужен полный минимальный пример синтаксиса с формой
  аргументов и результата; нельзя перечислять требования, оставляя неизвестные
  имена options вроде `method`, `headers` или `body` на догадку;
- пользователь пишет основную часть кода самостоятельно;
- ассистент никогда не присылает готовое исправление кода текущего учебного
  задания без отдельной явной просьбы; review содержит проблему, причину и
  требуемое изменение словами;
- при вопросе о незнакомом синтаксисе нужен минимальный пример только этой
  конструкции на нейтральном материале, без готового решения текущего задания;
- проверка кода после каждого шага;
- при проверке проекта нужны отдельные замечания и советы по HTML/CSS, а не
  только по React/JavaScript; форматирование пробелов само по себе не является
  приоритетом;
- сравнение с Vue там, где оно помогает пониманию;
- русский язык объяснений.
- учебные документы и журнал прогресса обновляются автоматически после
  значимых шагов, без отдельного напоминания пользователя.

## Технологический порядок

1. React + JavaScript + Vite.
2. HTML/CSS и SCSS внутри проекта.
3. Styled Components как второй способ стилизации.
4. REST API и асинхронная работа.
5. Тестирование.
6. TypeScript после устойчивой базы React, если останется время до отбора.
