## 1. Как браузер применяет CSS

CSS — **Cascading Style Sheets**, «каскадные таблицы стилей». Браузер работает
не с JSX-компонентами, а с созданным ими DOM — **Document Object Model**,
объектной моделью документа.

Упрощённая цепочка:

```text
JSX создаёт DOM-элементы
        ↓
CSS-селекторы находят подходящие элементы
        ↓
каскад выбирает победившее значение каждого свойства
        ↓
браузер вычисляет размеры и расположение коробок
        ↓
элементы рисуются на экране
```

CSS-правило состоит из селектора и деклараций:

```css
.todo-item {
  padding: 8px;
  border: 1px solid black;
}
```

- `.todo-item` отвечает на вопрос «к каким элементам применить правило?»;
- `padding: 8px` — декларация из свойства и значения;
- одно правило может совпасть с несколькими элементами;
- один элемент обычно совпадает сразу с несколькими правилами.

Поэтому CSS нельзя понимать как последовательность команд. Это система правил,
которые одновременно претендуют на свойства элементов.

## 2. Селекторы

### Класс, элемент и идентификатор

```css
.todo-item {}  /* class="todo-item" */
button {}      /* все <button> */
#search {}     /* id="search" */
```

Классы подходят для оформления переиспользуемых элементов. Селектор `id`
слишком специфичен для обычной стилизации и чаще нужен для связи HTML-элементов,
например `label[for]` с `input[id]`.

### Один элемент с несколькими классами

```css
.todo-item.completed {}
```

Пробела нет: требуется один элемент, у которого одновременно есть оба класса.

```html
<li class="todo-item completed">
```

### Потомок

```css
.todo-item .todo-title {}
```

Пробел означает: найти `.todo-title` на любой глубине внутри `.todo-item`.

### Непосредственный ребёнок

```css
.todo-nav > a {}
```

`>` требует, чтобы ссылка была непосредственным ребёнком `.todo-nav`. Если
между ними появится дополнительный `div`, правило перестанет совпадать.

### Атрибут

```css
[disabled] {}
.todo-layout[data-theme="dark"] {}
```

Первый селектор ищет любой элемент с атрибутом `disabled`. Второй требует один
элемент с классом и указанным значением атрибута.

### Псевдокласс

Псевдокласс описывает состояние существующего элемента и пишется с одним `:`:

```css
button:hover {}
button:disabled {}
input:checked {}
a:focus-visible {}
```

### Псевдоэлемент

Псевдоэлемент создаёт выбираемую CSS-часть элемента и пишется с `::`:

```css
dt::after {
  content: ":";
}
```

`::after` не добавляет настоящий React/HTML-узел и не подходит для важного
содержимого, которое должно существовать независимо от CSS.

## 3. Каскад и специфичность

Когда несколько правил задают одно свойство одному элементу, браузер выбирает
победителя. Для обычных авторских правил важен такой порядок рассуждения:

```text
важность → специфичность → порядок в файле
```

### Специфичность сравнивается по разрядам

Упрощённая запись:

```text
(inline, id, class/attribute/pseudo-class, element/pseudo-element)
```

Примеры:

```text
button                    → (0, 0, 0, 1)
.todo-button              → (0, 0, 1, 0)
.todo-actions button      → (0, 0, 1, 1)
#app .todo-button         → (0, 1, 1, 0)
```

Разряды сравниваются слева направо, а не складываются в одно число. Один `id`
побеждает любое количество классов в более правом разряде.

Если специфичность одинакова, побеждает декларация, расположенная позже.
`!important` меняет обычный порядок важности и затрудняет дальнейшее
переопределение, поэтому в проекте его не используют без отдельной причины.

### Что означает зачёркнутая декларация в DevTools

Зачёркнутое свойство совпало с элементом, но проиграло каскад другому значению.
Незачёркнутое свойство победило каскад, однако всё равно может визуально не
работать в текущей раскладке. Например, `flex-grow` не действует, если элемент
не является flex-элементом.

## 4. Наследование

Наследование передаёт вычисленное значение свойства от родителя потомку. Оно не
зависит от имени класса: наследует DOM-потомок, а не «вложенный CSS-класс».

Часто наследуются:

- `color`;
- `font-family`, `font-size`, `font-weight`, `line-height`;
- CSS custom properties вида `--focus-color`.

Обычно не наследуются:

- `margin`, `padding`, `border`;
- `width`, `height`;
- `display`;
- `background`;
- flex- и grid-настройки.

```css
.todo-layout {
  color: black;
  font-family: Arial, sans-serif;
}
```

Текст потомков получит эти значения, если более подходящее правило их не
переопределит. Но `padding` родителя создаёт пространство внутри родительской
коробки и не копируется каждому ребёнку.

Полезные ключевые слова:

```css
color: inherit; /* явно взять вычисленное значение родителя */
color: initial; /* взять начальное значение свойства из спецификации */
color: unset;   /* inherit для наследуемого свойства, initial для остальных */
```

## 5. Box model и размеры

Каждый отображаемый элемент создаёт прямоугольную коробку:

```text
margin
└── border
    └── padding
        └── content
```

- `content` — содержимое;
- `padding` — внутреннее пространство между содержимым и границей;
- `border` — граница;
- `margin` — внешнее пространство между этой коробкой и соседями.

### `box-sizing`

При стандартном `content-box` заданная `width` относится только к content, а
padding и border прибавляются снаружи. В проекте используется:

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

Теперь `width` включает content, padding и border. Это делает расчёт размеров
предсказуемее.

### Сокращённая запись отступов

```css
margin: 40px auto;
padding: 0 16px;
```

При двух значениях первое применяется сверху и снизу, второе — слева и справа.
Поэтому `margin: 40px auto` создаёт вертикальный отступ 40px и делит свободное
горизонтальное место поровну между автоматическими левым и правым margin.

```css
.todo-layout {
  max-width: 600px;
  margin: 40px auto;
  padding: 16px;
}
```

`max-width` только ограничивает рост. Без горизонтальных `auto`-отступов блок
ограниченной ширины остаётся у левого края.

## 6. Внешний и внутренний display

У элемента есть поведение относительно соседей и способ раскладки собственных
детей.

### `block`

```css
display: block;
```

Элемент участвует снаружи как блочная коробка и начинает новую строку. Внутри
его дети располагаются в обычном потоке.

### `inline`

```css
display: inline;
```

Элемент располагается в строке текста. Обычные `width` и `height` для него не
работают так же, как для блока.

### `inline-block`

Снаружи находится в строке, но сохраняет цельную коробку, для которой работают
размеры и вертикальные padding.

### `flex`

```css
display: flex;
```

Снаружи элемент ведёт себя как block, а его непосредственные дети внутри
становятся flex-элементами.

### `grid`

Снаружи элемент также является блочной коробкой, а непосредственные дети
раскладываются по строкам и колонкам Grid.

### Fragment не создаёт коробку

React Fragment `<>...</>` не появляется в DOM и не создаёт CSS-контейнер.
Поэтому его дети становятся непосредственными детьми ближайшего настоящего
HTML-родителя. Замена Fragment на `div` меняет DOM-иерархию, а значит может
изменить, какие элементы являются flex/grid-элементами.

## 7. Ширина, переполнение и обрезание текста

### `width` и `max-width`

```css
width: 600px;      /* стремиться иметь ровно 600px */
max-width: 600px;  /* не становиться шире 600px */
```

Для адаптивного контейнера чаще подходит `max-width`: на узком экране он может
сжаться, а на широком перестаёт расти.

### Почему flex/grid-элемент иногда не сжимается

У flex- и grid-элементов автоматический минимальный размер часто учитывает
ширину содержимого. Длинный текст может вытолкнуть кнопки за границу. Для
сжимаемого участка обычно требуется:

```css
min-width: 0;
```

Это не делает ширину нулевой. Оно разрешает алгоритму раскладки сжать элемент
меньше естественной ширины текста.

### Многоточие

```css
.content {
  min-width: 0;
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

Свойства работают вместе:

- `white-space: nowrap` запрещает перенос;
- `overflow: hidden` скрывает вышедшую часть;
- `text-overflow: ellipsis` рисует многоточие;
- контейнер должен иметь реальное ограничение ширины и возможность сжиматься.

Если между layout-контейнером и текстом добавлена ссылка, каждый промежуточный
уровень должен участвовать в передаче ограничения: например, ссылка становится
flex-контейнером и получает `flex: 1; min-width: 0`.

## 8. Flexbox

Flexbox — одномерная раскладка: элементы располагаются прежде всего вдоль одной
главной оси.

### Контейнер и элементы

```css
.container {
  display: flex;
}
```

Только непосредственные дети `.container` становятся flex-элементами.

Свойства контейнера:

| Свойство | Назначение |
|---|---|
| `flex-direction` | направление главной оси |
| `justify-content` | распределение по главной оси |
| `align-items` | выравнивание по поперечной оси |
| `gap` | промежутки между элементами |
| `flex-wrap` | разрешение переноса на новые строки |

Свойства flex-элемента:

| Свойство | Назначение |
|---|---|
| `flex-grow` | какую долю свободного места можно получить |
| `flex-shrink` | насколько элемент может сжиматься |
| `flex-basis` | базовый размер перед распределением пространства |
| `flex` | сокращение трёх свойств выше |
| `align-self` | индивидуальное выравнивание по поперечной оси |
| `order` | визуальный порядок без изменения DOM |

### Главная и поперечная оси

```text
flex-direction: row
главная ось      → слева направо
поперечная ось  → сверху вниз

flex-direction: column
главная ось      → сверху вниз
поперечная ось  → слева направо
```

`justify-content` всегда работает по главной оси, а `align-items` — по
поперечной. Их действие нельзя запоминать только как «горизонталь/вертикаль»:
оси меняются вместе с `flex-direction`.

### `flex: 1`

```css
.item {
  flex: 1;
}
```

Практически это означает:

```css
flex-grow: 1;
flex-shrink: 1;
flex-basis: 0;
```

Если два непосредственных flex-элемента имеют `flex: 1`, они делят свободное
место поровну. Свойство задаётся детям, а не flex-контейнеру.

```css
.todo-nav {
  display: flex;
}

.todo-nav-link {
  flex: 1;
  text-align: center;
}
```

`justify-content: space-between` только размещает узкие элементы по краям, но не
растягивает их кликабельные коробки. `flex: 1` растягивает сами элементы.

### `align-items: stretch`

Начальное значение `align-items` у flex-контейнера — `stretch`. Если размер по
поперечной оси не задан явно, непосредственные дети растягиваются по этой оси.

Текущий пример:

```text
.todo-layout: flex-direction column
└── поперечная ось горизонтальна
```

Когда 404-page возвращала Fragment, `h1`, `p` и `button` были непосредственными
flex-элементами `.todo-layout` и растягивались по ширине. После оборачивания:

```html
<div class="not-found-page">
  <h1>...</h1>
  <p>...</p>
  <button>...</button>
</div>
```

только `.not-found-page` осталась flex-элементом `.todo-layout`. Внутренние
элементы перешли в обычную раскладку `div`, поэтому кнопка снова получила ширину
по содержимому. Чтобы сделать wrapper новым вертикальным flex-контейнером:

```css
.not-found-page {
  display: flex;
  flex-direction: column;
}
```

Один элемент может одновременно быть flex-элементом относительно родителя и
flex-контейнером относительно собственных детей.

### Автоматический margin во Flexbox

```css
.button {
  margin-left: auto;
}
```

Левый автоматический margin забирает доступное свободное место и отодвигает
элемент вправо. DOM-порядок при этом не меняется.

## 9. Grid

Grid — двумерная раскладка по колонкам и строкам.

```css
.todo-item {
  display: grid;
  grid-template-columns: minmax(0, 1fr) auto;
  gap: 8px;
}
```

- `fr` — **fraction**, доля оставшегося пространства;
- `1fr` получает одну долю;
- `auto` подстраивается под содержимое;
- `minmax(0, 1fr)` разрешает первой колонке сжиматься до нуля и затем получать
  оставшееся пространство;
- `gap` создаёт промежуток между grid-элементами.

В Todo первая колонка содержит checkbox и название, а `auto` оставляет кнопкам
ровно необходимую ширину. На узком экране используется одна колонка, поэтому
actions переходят под название.

## 10. Адаптивность и media queries

Media query — условие применения CSS, основанное на характеристиках browser
viewport или устройства:

```css
@media (min-width: 560px) {
  .todo-item {
    grid-template-columns: minmax(0, 1fr) auto;
  }
}
```

Mobile first означает, что базовые правила рассчитаны на узкий экран, а
`min-width` постепенно добавляет возможности для более широкого.

```text
базовый CSS              → одна колонка
viewport не уже 560px    → две колонки
```

Media query получает ширину у браузера. React в этом выборе не участвует.
Viewport meta tag сообщает мобильному браузеру, как интерпретировать ширину
страницы, но не передаёт данные непосредственно в media query.

Для hover-стилей полезна проверка устройства, действительно поддерживающего
наведение:

```css
@media (hover: hover) {
  button:not(:disabled):hover {
    background: var(--button-hover-bg);
  }
}
```

## 11. Состояния элементов и доступность

### `:hover`

Применяется, когда указатель находится над элементом. Hover не должен быть
единственным способом получить важную информацию: у touch-устройств нет
обычного постоянного наведения.

### `:focus` и `:focus-visible`

`:focus` совпадает с текущим сфокусированным элементом. `:focus-visible`
совпадает, когда браузер считает визуальный focus ring нужным, прежде всего при
клавиатурной навигации.

```css
.todo-layout a:focus-visible {
  outline: 2px solid var(--focus-color);
  outline-offset: 2px;
}
```

Нельзя просто удалять `outline`, не предоставив заметной замены. Focus ring
отвечает на вопрос «какой элемент сейчас активирует Enter или Space».

### `:disabled`

Нативный `disabled` запрещает взаимодействие и выводит form-control из обычной
последовательности Tab. CSS должен только визуально дополнять это состояние:

```css
button:disabled {
  opacity: 0.5;
  cursor: not-allowed;
}
```

`button:not(:disabled):hover` не применяет hover-оформление к заблокированной
кнопке.

### Активная навигационная ссылка

React Router `NavLink` автоматически добавляет активной ссылке
`aria-current="page"`. Визуальный класс должен дублировать это состояние для
зрячего пользователя, причём не только изменением цвета. Это не то же самое,
что focus: активной может быть одна страница, а клавиатурный focus в этот момент
находится на другом элементе.

В проекте активный пункт отличается насыщенностью и толщиной подчёркивания.
Focus ring назначен базовому `.todo-nav-link:focus-visible`, а не только
`.todo-nav-link--active:focus-visible`: клавиатурный focus часто находится как
раз на неактивной ссылке, которую пользователь собирается открыть.

## 12. CSS custom properties и тема

CSS custom property остаётся в браузере и участвует в каскаде:

```css
.todo-layout {
  --surface-color: white;
  --text-color: black;

  background: var(--surface-color);
  color: var(--text-color);
}

.todo-layout[data-theme="dark"] {
  --surface-color: black;
  --text-color: white;
}
```

Custom properties наследуются потомками. Поэтому кнопки и ссылки могут читать
цвет темы, не зная, на каком именно предке он объявлен.

Нужно отличать:

- `--text-color` — runtime-переменная CSS, существует в браузере;
- `$space-small` — Sass-переменная сборки, исчезает после компиляции.

## 13. SCSS

Sass — **Syntactically Awesome Style Sheets**. SCSS — **Sassy CSS**, CSS-подобный
синтаксис Sass. Браузер не выполняет SCSS: Vite запускает Sass-компилятор и
включает получившийся обычный CSS в сборку.

### Вложенность и `&`

```scss
.todo-layout {
  button { /* .todo-layout button */ }

  &[data-theme="dark"] {
    /* .todo-layout[data-theme="dark"] */
  }
}
```

Без `&` вложенный селектор становится потомком. `&` обозначает полный текущий
родительский селектор и позволяет добавить состояние, класс или атрибут тому же
элементу. Глубокая вложенность создаёт слишком специфичные и хрупкие селекторы,
поэтому её ограничивают несколькими осмысленными уровнями.

### Переменные и mixins

```scss
$space-small: 8px;

@mixin focus-ring($color: var(--focus-color), $offset: 2px) {
  outline: 2px solid $color;
  outline-offset: $offset;
}

button:focus-visible {
  @include focus-ring($offset: 2px);
}
```

Mixin — переиспользуемая группа деклараций. Именованный аргумент позволяет
изменить конкретный параметр, не меняя предыдущие параметры по позиции.

### Partials и modules Sass

Файл `_tokens.scss` является partial — частью общей таблицы стилей. Он
подключается так:

```scss
@use "./styles/tokens";

.todo-item {
  gap: tokens.$space-small;
}
```

`@use` создаёт namespace и загружает модуль один раз. JavaScript импортирует
только основной `index.scss`; partial-файлы находит Sass во время сборки.

## 14. Глобальный CSS, CSS Modules и CSS-in-JS

### Глобальный SCSS

Обычный `index.scss` создаёт глобальные селекторы. Он подходит для reset,
типографики, layout, theme custom properties и общих состояний. Совпадение имён
классов разработчик предотвращает соглашениями об именовании.

### CSS Modules

Файл должен называться `*.module.css` или `*.module.scss`:

```jsx
import styles from "./TodoContent.module.scss"

<span className={styles.content} />
```

Vite преобразует локальное имя в уникальное собранное имя. Это защищает от
случайного совпадения названий между модулями, но не создаёт Shadow DOM и не
отменяет каскад.

### CSS-in-JS и Styled Components

CSS-in-JS — **CSS in JavaScript**, стили в JavaScript. Styled Components —
конкретная runtime-библиотека этого подхода:

```jsx
const PriorityButton = styled.button`
  font-weight: ${({ $important }) => $important ? 700 : 400};
`
```

Компонент объявляется вне React-компонента, иначе на каждом рендере создавался
бы новый тип. Styling props с `$` не передаются в DOM. Generated class всё равно
участвует в обычной специфичности и может проиграть глобальному правилу.

### Как выбирать

| Подход | Основная польза |
|---|---|
| Глобальный SCSS | reset, layout, общие tokens и states |
| CSS Modules | локальные классы компонентов |
| Styled Components | динамические стили, тесно связанные с props/theme |

Подходы можно сочетать, но в реальной команде важнее единое соглашение, чем
использование всех технологий одновременно.

## 15. Как отлаживать CSS

Последовательность проверки:

1. Убедиться, что JSX создал ожидаемый DOM и нужный `className`.
2. Проверить в DevTools, совпал ли селектор с элементом.
3. Если декларация зачёркнута — найти правило, победившее каскад.
4. Если декларация не зачёркнута, проверить контекст: является ли элемент
   flex/grid-элементом, есть ли ограничение ширины, подходит ли ось.
5. Посмотреть computed value и размеры box model.
6. Проверить узкий viewport, длинный текст, keyboard focus, disabled и тему.

Частые причины «свойство не работает»:

- селектор не совпал с реальным DOM;
- правило проиграло специфичности;
- свойство задано не контейнеру или не элементу;
- добавленный wrapper изменил непосредственных детей;
- содержимое запрещает сжатие без `min-width: 0`;
- свойство победило каскад, но не действует при текущем `display`;
- shorthand одновременно перезаписал несколько longhand-свойств.

## 16. Проверенные схемы текущего проекта

### Центрированный адаптивный layout

```scss
.todo-layout {
  max-width: 600px;
  margin: 40px auto;
  padding: 16px;
}
```

### Задача: текст плюс actions

```scss
.todo-item {
  display: grid;
  grid-template-columns: minmax(0, 1fr) auto;
}
```

Первая колонка получает остаток и может сжиматься, вторая сохраняет ширину
кнопок.

### Растянутые пункты навигации

```scss
.todo-nav {
  display: flex;
}

.todo-nav-link {
  flex: 1;
  text-align: center;
  padding: 8px;
}
```

Ссылки являются непосредственными flex-элементами и делят ширину поровну.

### Wrapper как flex-элемент и flex-контейнер

```scss
.not-found-page {
  display: flex;
  flex-direction: column;
}
```

`.not-found-page` растягивается как ребёнок `.todo-layout` и одновременно
управляет собственными непосредственными детьми. Это два разных уровня одной
DOM-иерархии.
